# Project roadmap

This is a proposed delivery sequence, not a fixed estimate or an approved implementation plan. Budget amount, deadline, catalogue size and operational requirements are not yet supplied. Prioritise quality of the ordering system before optional visual features.

| Phase | Deliverables | Exit condition | Status |
|---|---|---|---|
| 1. Research and discovery | Folder scan, public-site audit, URL inventory, competitors, this vault | Findings traceable and unknowns explicit | This research pass delivered |
| 2. Brand and operational definition | Guide identity/palette/12 families; remaining fonts/logo masters/rates/policies | Brand baseline established; operations/assets resolved | Guide reviewed; remaining inputs pending |
| 3. Sitemap and wireframe review | Page tree, per-page section structures, annotated homepage, guide mapping | Review routes and layout; resolve changes | Delivered for review |
| 4. HTML prototype | First review slice, then agreed templates and states | Client reviews visual system and key journeys; prototype QA recorded | Not started |
| 5. WordPress implementation | Staging theme, content/product models, cart, gateway, quote/upload/proof operations | Functional and operational acceptance | Not started |
| 6. Content and migration | Approved copy/media/rates, route mapping, data migration rehearsal | Content/data checks and redirects signed off | Not started |
| 7. Launch and handover | Approved release, post-launch checks, staff training, recovery documentation | Production acceptance and ownership clear | Not started |

## Suggested work packages

Foundation/brand; catalogue and configuration; quote/artwork/proof; checkout/payment/fulfilment; content/SEO/migration; QA/training/release. Keep these independently tracked so the project does not become only a homepage-design exercise.

## Launch essentials — proposed priority

Clear mobile shop; approved first catalogue; valid prices and options; product-line artwork; quote route; verified gateway results; realistic delivery/pickup; required staff proof process; accessible forms; email/status; meaningful company/help/policy pages; route preservation and backups.

## Later candidates

Reorders and saved specifications; fuller finish/sample comparison; bundles; selected template editor; advanced corporate workspaces; automated courier/WhatsApp integration. Validate demand and maintenance cost before scheduling them. Rich animation, global marketplace and ERP replacement are not assumed scope.

## Major dependencies

Guide received; master logo/webfont files and photography; approved rate card; production staff; gateway account/plugin access; hosting; product photography; policy approval; current data/integration exports; catalogue/editor selection.

## Definition of ready for HTML

At least the visual brand rules, first product examples, chosen experience, and simulated customer flows are clear. Where business information remains unresolved, the prototype must label it and avoid invented promises. Create a detailed executable implementation plan after reviewing this research/design proposal.
